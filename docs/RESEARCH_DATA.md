# 研究參與（選填）：資料說明

這份文件說明「研究參與」功能收集什麼、不收集什麼、怎麼運作。內容可以直接引用在論文的研究方法／倫理說明裡（仍請依你學校的研究倫理審查要求補充）。

## 目的
了解使用者「哪一週用過哪些 App」，作為開發者論文的使用情形資料。

## 參加方式（自願、預設關閉）
- 功能預設**關閉**。只有開發者在 `js/core/research-config.js` 填入自己部署的接收端網址後，設定裡才會出現「研究參與（選填）」。沒填網址時，整個功能隱藏、不會有任何網路請求。
- 使用者要在設定頁讀完說明、按下「我了解，願意參加」並再確認一次同意，才會開始記錄。
- 開啟 App 一定次數後會**只問一次**要不要參加（純本機計數）；選「不用了」就不會再問。
- **未滿 18 歲或尚未設定生日的使用者完全不會看到這個功能**，也不會被記錄或送出任何資料。
- 隨時可以「停止參加」；也可以「停止參加並刪除我已送出的資料」，會請接收端刪除該匿名編號的全部資料，並換掉匿名編號。

## 收集的資料（只有四個欄位）
```json
{ "v": 1, "pid": "隨機產生的匿名編號", "week": "2026-W43", "apps": ["chats", "music"] }
```
| 欄位 | 說明 |
|---|---|
| `v` | 資料格式版本 |
| `pid` | 同意參加時在使用者裝置上隨機產生的 UUID，與姓名、帳號、裝置無關；退出時會刪除或更換 |
| `week` | ISO 週別（例如 `2026-W43`），沒有日期、沒有時間點 |
| `apps` | 這週開啟過的 App 名稱，**只有「有／沒有」**，沒有次數、沒有停留時間；只可能是固定白名單內的 40 個名稱（見 `js/core/research-core.js` 的 `TRACKED_APPS`） |

每天最多送出一次，而且只有在清單有變動時才送。

## 絕對不收集
- 聊天內容、使用者輸入的任何文字、角色資料、AI 生成的任何內容
- API 網址與金鑰、備份、記憶、照片、位置
- 姓名、信箱、帳號
- 不儲存 IP 位址、User-Agent、裝置或瀏覽器資訊（請求不帶 cookie、不帶 referrer）
- 成人限定 App（酒館、約會、AO3、Lofter）與設定、通行密鑰、外觀、輔助觸控、說明等頁面**完全不記錄**

> 網路連線本身一定會讓接收伺服器看到連線來源（技術上避免不了）；接收端程式碼不讀取、不儲存這些資訊，且程式碼公開可檢查（`research-worker/`，有單元測試確認）。

## 怎麼保證
- **白名單**：不在名單內的名稱，用戶端不會記、接收端會拒絕（回 400）。名單不含任何使用者可輸入的內容。
- **嚴格格式**：接收端只接受剛好上述四個欄位；多一個欄位就整筆拒絕。用戶端與接收端共用同一份驗證程式碼（`js/core/research-core.js`）。
- **使用者看得到**：設定頁會顯示「實際會送出的資料」預覽。
- **可驗證**：`tests/unit/research-core.test.mjs`、`tests/unit/research-worker.test.mjs` 涵蓋白名單、格式、刪除、來源限制，並檢查接收端程式碼沒有讀取 IP／User-Agent。

## 接收端與保存
- 接收端是開發者自己 Cloudflare 帳號上的 Worker + D1 資料庫（`research-worker/`），資料表只有 `pid`、`week`、`apps` 三欄。
- 部署步驟見 [research-worker/README.md](../research-worker/README.md)。
- 研究結束後，請刪除資料庫（或整個 Worker），並在論文／公告中說明資料保存期限。

## 修改規則時
若改了收集內容或說明文字，請把 `js/core/research-config.js` 的 `CONSENT_VERSION` 加一：已同意的人需要重新同意才會繼續記錄。
